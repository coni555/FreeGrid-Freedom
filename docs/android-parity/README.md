## 使用规则

文中“现状”来自当前源码；“要求”是对齐时应满足的行为；“建议”是实现路线，尚未替用户作产品决策；“待定”不得自行变成收费、联网或分发承诺。

发生冲突时，优先采用用户最新决定和项目 AGENTS；代码、测试和文档不一致须显式记录，不能把已发现的缺陷当成迁移要求。规格更新时记录新的源码基线和受影响案例，不默默追逐不断变化的 main。

本轮最重要的三个结论：

1. 保留 Flutter 和已有 Android 适配，优先重建数据、计算与写入边界。
2. 当前 iOS 备份是 schema 2/3，固定支出和贷款都在 `loans`。Android 补丁所谓“iOS schema 4 / fixed_expenses”不符合这次基线。
3. 用户已定安卓一次上完全版；下面的阶段用于内部开发验收，不再建议发布免费缩水过渡版。渠道、支付和后续 2.2 / 2.3 纳入范围仍待定。

人工视觉验收与完整两端自动化测试仍是后续开发的完成条件。本包不是截图对齐报告。
