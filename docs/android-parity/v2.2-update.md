## 一、记账方式

产品规则以 iOS `AGENTS.md`「两种记账方式」为准，下面是最容易做错的几条：

- **两本账互不相干，不混算。** 切到按月后，日均只看写下的数，记录收起来不计入、不删除。切回逐笔立刻回到切换前，不过渡。
- **只写过数、从没记过账的人切回逐笔**：没有切换前可回，日均用 30 天从写下的数过渡到记录。
- **写的是当月全部花销，含固定支出。** 算日均时先扣固定支出：日常 = 写过月份的平均 − 固定支出（最小 0），日常日均 = 日常 ÷ 30.44。界面上的日均（`dailyCost`）仍是写下的数折成每天。
- **填数不扣现金。** 已设的固定支出仍到期扣现金。
- **不催。** 不推送、不角标、不做未写提醒，只有胶囊下一行「建议月底去记」。
- 问哪个月：看 `MonthlyTracking.prompt`。上个月过完没写先问上个月；隔几个月只问最近过完的那个月，不补更早的；`startMonth` 之前不问；月底最后 3 天不说「建议月底去记」。

### 数据

| 项 | 规则 |
|---|---|
| 本机偏好 | `SharedPreferences` 键 `monthlyTracking`，存 JSON |
| 备份字段 | 顶层可选 `monthly_tracking`：`method`（`entries`/`monthly`）、`months`（`"2026-11": 3000`）、`start_month`、`pauses`（`[{start, end}]`，ISO 8601）、`switched_back_at`。**`schema_version` 不变** |
| 从没用过 | 导出不写这一段（`isUntouched`） |
| 坏值 | 不拦整份备份：未知 method 当 `entries`，坏月份键、非正金额、坏日期丢掉 |
| 恢复 | `storedAfterRestoring`：`AssetsImportStrategy.replace` 以备份为准，备份没有就回到逐笔；其他策略本机用过就不动，没用过才补上 |
| 清空账本 | 记账方式一起清掉 |
| 校验金额 | 有限、大于 0、不超过 1e12（iOS `MonthlyTracking.valid` 用的 `FinancialLimits.maximumAmount`，安卓同值的是 `maxAssetAmount`） |

### 计算（`DailyBurn`）

直接照 `FreeGrid/Logic/DailyBurn.swift`、`MonthlyTracking.swift` 移植，常量同名同值：`burnGraceDays = 14`、`estimateBlendDays = 30`、`minRecordedDays = 3`、`monthEndDays = 3`。

快照要新增并全程传递：`hasRecords`、`tracking`、`fixedMonthly`、`burnBasis`、`burnGapDays`、`recordsTooFew`。`hasExpenses` 的新定义：

```
按月：写过至少一个月
逐笔：(有记录 且 不是 recordsTooFew) 或 basis == estimate
```

**所有构造快照的地方都要带上 tracking**：首页、钱包、明细日均、记账预览、模拟、趋势、小组件。漏一处就会两个页面两个数。

连带改动：

| 位置 | 改法 | iOS 来源 |
|---|---|---|
| 自由天数推演 | `freedomRun` 加 `burnMayBeZero`、`writtenDaily`：写的数全被固定支出占了不算数据错误，贷款还完后按写的数接着花 | `Logic/LoanSchedule.swift` |
| 12 周趋势 | `weeklyPoints` 带 tracking、fixedMonthly；按月或记录太少时不画 | `Logic/FreedomHistory.swift`、`DashboardView.swift` |
| 记账 / 模拟预览 | 带 tracking；按月时模拟不会让日均从无到有，也不问要不要记这一笔 | `Logic/TransactionImpact.swift` |
| 自检 | 记账里程碑看 `hasRecords`，按月时提示「用「按月记账」时暂停更新」 | `Logic/FreedomChecklist.swift` |
| 自由卡 | 记账天数看 `hasRecords`（代码保留，安卓入口关着） | `Logic/FreedomCard.swift` |
| 首页小卡 | `needsRecords`（month、today、track、todayBar），按月时隐藏但留在顺序里，切回还在；按月默认 `[daily, passive 或 base]`；`dailyNote` | `Logic/HomeStat.swift` |
| 小组件 | 免费的自由天数小组件：按月没数写「写下*每月花销*」，记录太少写「暂时*算不准*自由天数」 | `Logic/WidgetProjection.swift` |

## 二、界面

**页面结构、文案、层级都照 iOS。** 中文取 iOS 源码，英文取 `FreeGrid/Localizable.xcstrings` 的译文，不自己写。只有返回键、键盘、日期选择、触觉反馈按 Android 习惯。组件用现成的 `silverline.dart`、`form_sheet.dart`。

| 页面 | 要做的 | iOS 来源 |
|---|---|---|
| 首页 · 大数字卡 | 待显示状态的标题和小字（`pendingTitle`、`pendingNote`）；蓝字入口：算不出且不缺钱时「不想每天记账？改用「按月记账」」，断档时「上次记账是 N 天前。改用「按月记账」？」 | `Dashboard/DashboardHero.swift` |

## 三、不能破坏

- 正式签名、包名 `cn.conilab.freegrid` 不变；不碰 `android/key.properties` 和 keystore。
- 零 INTERNET，不加新依赖。
- 1.0 和 2.1 的账本、iOS 2.1 和 2.2 的备份都能直接导入。
- 2.1 验收过的计算案例继续通过；只有断档新规则必须改变结果的才改期望，改的逐条列出，以 iOS 2.2 行为为准。
- 不把 `onSale` 打开，不出现任何 Pro 入口。
- pubspec 升到 `2.2.0+13`。

### 人工（模拟器 Pixel 7，中英文、深浅色）

每项和 iOS 模拟器同一状态的截图比对，**不能只看测试通过**。

1. 空账本：大数字卡有蓝字入口，点开填数面板，「月底再记」后首页是胶囊，写数后出自由天数。
2. 有记录的账本切按月：警告面板写对笔数；确认后大数字先消失；明细只有写过的月份；钱包的数和首页一致。
3. 写第二个月：日均取平均，小卡小字「按 2 个月平均」，现金不变。
4. 切回逐笔：记录全回来，日均和切换前一分不差；首页小卡顺序还在。
5. 只写过数的账本切回逐笔，记一笔 20：日均不跳。
6. 记两笔隔 31 天：首页「暂时算不准自由天数」；断档的老账本大数字照常，多一行蓝字，日均卡写「N 天没记 · 日均先停住」。
7. 明细展开各类、只看一类、在这一类里搜索、切月、「看全部」。
8. 月度汇总柱状图和扇形图，同一分类跨月同色，10 个以上分类不崩。
9. 首页点「本月花销」到明细本月。
10. 备份：iOS 2.2 备份（含按月）导入，方式和数都对；再导出，`monthly_tracking` 一字段不少；iOS 2.1 备份和安卓 1.0 账本正常进。
11. 小组件：按月没数、记录太少两种文案，切换后刷新。
12. 全程英文下没有中文，中文下没有英文。
